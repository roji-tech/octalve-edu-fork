All routes live under `/api/v1/schools/[code]/academics/…`, so the route-discovery guard in `tests/api/tenant-boundary.spec.ts` covers every one of them (cross-school, signed-out, deactivated).

- **Sessions and terms.** A session is a school year (label, dates, whole school or one campus). One `ACTIVE` session per scope (partial unique index **and** a per-scope advisory lock). Opening a second one is refused naming the open one; `closeCurrent: true` closes it and opens the new one
  in one transaction (two audit rows). `CLOSED` is terminal and read-only. A campus's current session is its own active session if it has one, else the school-wide one (`currentSessionFor`, the only definition). Periods (`TERM`/`SEMESTER`/`COHORT`, derived from `Tenant.schoolType`, never
  accepted from the client) must lie inside the session, may not overlap (cohorts may), and at most one is current. **Copy-forward** shifts a session and its periods by whole years into a new planned session; a dry run writes nothing and reports clashes; a second copy is refused (`ALREADY_COPIED`).
- **Classes and subjects.** Class groups (per school or campus, ordered), arms (optional capacity), subjects (upper-cased unique code), and "which class studies which subject" saved as the full list (idempotent). Archiving a group with live arms (`HAS_ACTIVE_ARMS`) or a subject still offered (`SUBJECT_IN_USE`) is refused.
- **Assessment schemes.** Components + exam = total, exactly (arithmetic in integers of hundredths — `0.1 + 0.2` is refused, not rounded), 1–10 components, unique names. One live scheme per class group (or the school default). **Locked** by `lockScheme(tx, tenantId, id)` — the function Phase 1.4 calls the first time a result references a scheme — after
  which **database triggers** refuse any change to it or its components, whichever code writes (the owner role included; a whole-school cascade delete is the one allowed removal). A change to a locked scheme is `POST …/new-version` (version + 1, predecessor archived, `supersedesId` linked). `snapshotScheme` gives the canonical JSON + SHA-256 a result will store.
- **Grade scales.** Half-open contiguous bands `[min, max)` covering 0 to 100 (top band closed at 100), so no decimal score falls in a gap or two bands; `gradeFor` is the only way a score becomes a letter. Exactly one default per school (the first scale becomes it); make-default swaps in one transaction; the default cannot be archived. Same lock / new-version rule as schemes (a new version inherits the default flag).
- **Screens.** "Academic setup" at `/schools/[code]/academics?section=sessions|classes|assessment|grading` — administrators only (like Users: anyone else gets the same 403 view as a stranger); nav entry "Academics". Real links choose the section (reload and back work). Dialogs say what each action does and does not do (nothing is ever deleted); a refusal appears next to the field it concerns;
  results are announced in one polite live region; focus returns to the opener on close and to the list summary after a change that removed the focused row (no timers); phone layouts are cards; tap targets ≥ 44 px. The assessment form shows "components + exam = total" live; the copy-forward dialog **previews exactly what would be created, and any clash, before it creates it**.

## Findings and decisions (read these)
1. **A bug found by the tests, fixed.** A service that *returns* a refusal after it has already written commits the write: `newSchemeVersion`/`newScaleVersion` archived the predecessor and *then* checked the new name (`NAME_TAKEN`) — leaving the old version archived and no successor; `activateSession` with `closeCurrent` closed the open session and *then* found the target was not `PLANNED`;
   `setCurrentPeriod` and `makeDefaultScale` could (on a lost race) clear the old pointer and then refuse. **Fix:** check before the first write wherever possible (new versions), and otherwise throw so the transaction rolls back — `refuseAndRollBack` / `rollingBack` in `lib/academics/sessions.ts`. A regression test pins the activation case (the open session stays open). **Rule: a refusal that can follow a write must roll back.**
2. **Versioning as built differs slightly from the design text.** Decision 14 said a new version "archives nothing until it is activated"; as built the predecessor is archived **in the same transaction** (the one-live-per-scope and unique-name indexes need it out of the live set first, and a school never has two live schemes for one class). The lock is enforced by **triggers**, not only by the service (design: service; hardened because history that results will reference must not depend on a service having no bug).
3. **The page is administrators-only.** Design decision 18 had staff seeing the same pages read-only. The read API for staff exists and is tested (campus-scoped), but no staff screen was built: nothing in Slice 1 needs one, and a read-only variant is a screen to design with the Phase 1.2 people pages. (Flagged.)
4. **Copy-forward cannot invent a name for a non-year session label** (`2026/2027` → `2027/2028` is inferred; anything else must be typed). The dialog says so in words instead of showing a generic "not blank" error under an *optional* field (found by the accessibility run).
5. **Dates are spelled by a table**, not `Intl` ("7 Sep 2026"): the browser's locale data writes "Sept" in newer versions, and a server render and a browser could disagree.
6. Composite foreign keys `(tenantId, parentId) → parent(tenantId, id)` keep every row inside its own school even through the owner role; they use `ON DELETE NO ACTION` (a school delete cascades through `tenantId`). Prisma cannot create nested children with a composite tenant key, so services create the parent then `createMany` the children.
7. The route handlers do not trust path ids: an id that cannot be one of ours, an unknown id, another school's and another campus's all answer the **same 404** (asserted by comparing bodies).
8. Test-time: API and browser tests run the **production build** — run `pnpm build` after changing a route or a screen, or they test the old code (a wave of 404s is the symptom).
